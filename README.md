# 할 수 있어

교사용·학생용 화면을 분리한 학생 답안 기반 개별 학습 웹 서비스입니다.

## 처음 실행

Node.js 24 이상에서 다음 명령을 실행합니다. Windows에서는 `실행.cmd`를 열어도 됩니다.

```sh
npm ci
npm start
```

교사: http://localhost:4173/teacher · 학생: http://localhost:4173/student

최초 실행 시 시연 학급과 학생, 밀도 학습지, 우리은하·조선 건국·순환계 수업자료를 준비합니다. `materials/`에는 PDF 3개와 페이지별 검색 본문을 포함합니다. RAG 로컬 검색은 키 없이 작동합니다. 실행 후 생성되는 `data/`는 Git에 포함하지 않습니다.

실제 GPT와 OCR을 사용하려면 `.env.example`을 참고해 `.env`를 설정합니다. 기본 실행은 로그인 화면 없는 로컬 시연용이며, 실제 학교 운영용 인증·권한 구성은 추가해야 합니다.

## AI와 RAG 함께 연결하기

BAZE 연결을 지원합니다. 기본 대화 모델은 `gpt-5.6-sol`, 임베딩 모델은 `text-embedding-3-small`입니다. 웹앱 전용 키는 `.env`의 `THINKMATE_BAZE_API_KEY`에 저장하며 공용 `BAZE_API_KEY`보다 우선합니다. Codex 앱과 다른 키를 사용해도 Windows 사용자 환경변수나 Codex 설정을 수정하지 않습니다. 전용 키가 없으면 서버 환경변수 `BAZE_API_KEY`를 사용할 수 있습니다. `.env`에서는 `AI_PROVIDER=baze`, `BAZE_MODEL`, `BAZE_EMBEDDING_MODEL`을 설정할 수 있습니다. `AI_PROVIDER=openai`로 지정하면 기존 OpenAI 연결을 사용하며 서비스별 키를 구분합니다.

1. 서버 실행 후 교사 사이트의 `API 연결` 화면(`/teacher?view=settings`)을 엽니다.
2. **BAZE API Gateway** 또는 **OpenAI**를 선택하고 해당 서비스의 API 키와 GPT·임베딩 모델을 입력한 뒤 **연결 검증 및 RAG 적용**을 누릅니다. 같은 서비스의 서버 키가 이미 설정되어 있으면 키 입력을 비워둘 수 있습니다. 검증한 키는 서버 `.env`에 저장하며 브라우저·학급 DB·로그에 반환하지 않습니다.
3. 연결되면 문제 생성, 교사·학생 답안 채점, 학생 복습 대화와 새 확인 문제 생성, 복습 확인 문제 채점에 공통으로 적용됩니다. RAG는 Embeddings API로 자료와 검색어를 임베딩하고 본문 검색과 결합합니다. 검색한 원문은 문제 생성과 복습 대화에 전달됩니다.
4. 자료를 바꾸거나 임베딩 생성에 실패했다면 **RAG 임베딩 갱신**을 누르고 **자료 검색 테스트**에서 출처와 페이지를 확인합니다. 연결 검증 성공과 자료 임베딩 완료는 별도로 확인하세요.

학생은 모든 유형의 학습지를 웹에서 풀 수 있습니다. API 연결 시 교사 채점과 같은 기준으로 의미를 평가하고, 판단이 어려운 답안은 교사 검토로 남깁니다. AI 오류 시 기존 채점 기록을 유지하며 오류를 표시합니다. API 키가 없으면 기존 로컬 시연 모드를 사용합니다. 학생용 API에는 확인 문제의 정답·채점 기준을 전달하지 않습니다.

교사 화면의 **학습지 제작 → 생성된 학습지**에서 학습지별 폴더를 열면 제출 인원·제출자 평균·학습 완료 인원과 학생별 제출·점수·복습 상태를 확인할 수 있습니다. 모바일에서는 학생별 카드로 표시합니다. ‘기록 보기’는 해당 학습지의 답안과 복습 대화로 연결되고, 목록으로 돌아오면 같은 폴더를 유지합니다. 추가 학습이 필요한 학생은 완료 인원에서 제외하며, 학생이 다른 학습지를 시작해도 이전 학습지의 복습 기록을 유지해 표시합니다.

일반 `npm test`는 유료 호출을 하지 않습니다. 실제 BAZE 연결은 서버 환경변수에 `BAZE_API_KEY`를 설정한 뒤 `node tools/verify-baze.mjs`로 검사할 수 있습니다. 이 검사는 별도 임시 DB에서 연결 검증, 시연 자료 임베딩, 검색, 문항 생성, 교사·학생 채점, 복습 대화와 독립 문제 채점을 수행하며 BAZE 사용료가 발생합니다. 연결 검증 API는 프로젝트 `.env`에 검증된 설정을 저장합니다. 기존 학급의 학습 기록은 변경하지 않습니다.

BAZE의 공식 [Responses API](https://docs.factchat.kr/docs/general/api-gateway/reference/responses-api)와 [Embeddings API](https://docs.factchat.kr/docs/general/api-gateway/reference/embeddings)를 사용합니다. API 주소는 서비스별로 고정하고 인증 요청의 리디렉션을 허용하지 않습니다.

검증: `npm run check`, `npm test`.

# 할 수 있어 — 교사·학생 사이트

하나의 Node 백엔드와 SQLite DB에 연결된 서로 다른 웹 사이트입니다.

- 시작: http://localhost:4173/
- 교사용: http://localhost:4173/teacher
- 학생용: http://localhost:4173/student

## 실행과 시연

Node.js 24 이상. 실행.cmd를 더블클릭하면 최초에 필요한 패키지를 설치한 후 실행합니다. 터미널에서는 최초 `npm ci`, 이후 `npm start`를 실행합니다.

1. 교사 사이트에 접속하면 로그인 화면 없이 관리 화면이 바로 열립니다.
2. 학급 현황의 ‘학생별 접속 코드 · 링크 확인’을 엽니다.
3. 학생에게 본인의 링크를 전달하면 코드 입력 없이 해당 공부방이 열립니다. 일반 학생 주소는 시연 학생의 공부방으로 자동 접속합니다.
4. 교사는 수업 자료·학습지·답안을 등록하고 채점합니다. 학습지는 해당 반 학생의 과제에 나타납니다.
5. 학생은 오답으로 세 번 대화하고 독립 문제를 풉니다.
6. 결과는 서버에 저장되며 교사 화면에 3초 간격으로 반영됩니다. 학생 과제 목록도 3초 간격으로 갱신됩니다.

초기 밀도 시연 데이터가 포함되어 있으며 기존 DB가 있으면 유지합니다.

## 데이터와 역할 분리

- 교사 `/api/teacher/*`, 학생 `/api/student/*`로 API와 쿠키 인증을 구분합니다.
- 학생 ID는 요청 본문 대신 서버 세션에서 결정합니다.
- 학생 API는 타 학생 정보, 전체 학급 상태, 독립 문제의 정답·채점 기준을 반환하지 않습니다.
- 학생이 보낸 correct/session/check 객체를 평가 근거로 사용하지 않습니다. 서버에 저장된 세션·정답으로 평가합니다.
- 교사의 자료 저장이 최신 학생 대화를 덮어쓰지 않습니다. 다른 교사 창과 동시 편집 시 버전 충돌을 감지합니다.
- SQLite 위치: data/thinkmate.sqlite. 반·학생·학습지·답안·대화·접속 코드·인증 세션을 저장합니다.
- 쿠키는 HttpOnly·SameSite=Strict, 8시간 뒤 만료됩니다. 로그아웃 시 서버 세션도 폐기합니다.

## 실제 GPT·OCR 연결

.env.example을 .env로 복사해 OPENAI_API_KEY, 사용 가능한 OPENAI_MODEL을 설정한 뒤 서버를 재시작하세요. 교사 비밀번호는 TEACHER_PASSWORD로 설정합니다. 키는 서버에서만 사용합니다.

실제 모드에서는 수업 자료를 다시 등록해 RAG 색인을 생성하세요. TXT/MD·직접 입력한 텍스트의 청크 임베딩을 SQLite에 저장하고 관련 자료 상위 5개를 검색합니다. PDF 본문 추출은 별도 백엔드에서 연결해야 합니다.

OCR_BACKEND_URL로 OCR 서버를 연결합니다. 연결 없이 ‘시연 답안으로 체험’을 사용할 수 있습니다. GPT 키가 없으면 밀도 단원의 규칙 기반 대화이며 화면에도 표시합니다. 서술형 로컬 채점은 교사 검토로 남깁니다. 실제 AI·OCR 호출은 연결 정보가 없어 검증하지 않았습니다.

PDF는 교사 수업 관리 → 학습지 제작 → 학습지 열기 → PDF로 저장에서 브라우저 인쇄 기능을 사용합니다. 학생용 출력에는 정답과 채점 기준을 제외합니다.

## 검증과 범위

`npm run check`, `npm test`. AI 채점·RAG·복습 테스트와 별도 임시 DB·로컬 HTTP 서버를 사용하는 역할·권한·연동 통합 테스트가 있습니다.

이 서버는 127.0.0.1에 바인딩하는 로컬 시제품입니다. 현재는 로그인 화면 없이 시연용 세션을 자동 생성합니다. 학생별 API와 데이터는 분리되지만 교사 주소도 바로 열리므로 운영용 인증으로 사용하면 안 됩니다. 다수 교사 계정·교사별 반 소유권·비밀번호 복구·접속 코드 회전·운영 감사 기능은 후속 범위입니다. 기본 비밀번호는 시연용이며 외부 운영 전 변경하고 HTTPS·호스팅을 구성해야 합니다.

학급 요약은 규칙 기반 집계입니다. 단독 HTML은 로컬 사이트 선택 화면이며 DB 연결에는 서버가 실행 중이어야 합니다. API 규격은 API_CONTRACT.md를 참고하세요.

로그인 없는 시연: GET /api/teacher/me와 GET /api/student/me는 쿠키가 없으면 각 역할의 시연 세션을 자동 발급합니다. 학생 접속 링크의 코드는 학생 식별에 계속 사용합니다.


## RAG 검색과 API 연결

- 자료 검색: http://localhost:4173/teacher?view=rag
- API 연결: http://localhost:4173/teacher?view=settings

자료는 페이지를 보존해 최대 650자, 중첩 100자 청크로 나누고 SQLite rag_documents/rag_chunks에 저장합니다. 한국어 단어와 2·3글자 단위의 BM25 본문 검색은 API 키 없이 작동합니다. 검색 결과에 자료명·쪽·추출 방식이 포함됩니다. 자료 내용이 변경되면 해당 자료의 색인을 다시 만듭니다.

OpenAI 키가 있으면 임베딩과 본문 검색을 결합합니다. API 연결 화면에서 키와 사용 가능한 모델을 입력하면 임베딩 요청 및 GPT 응답 요청을 실제로 검증하고, 성공한 키만 .env에 저장합니다. 키는 브라우저 저장소나 학급 상태 DB에 저장하지 않습니다. 이어서 자료 임베딩을 생성합니다. 키가 없는 현재 환경에서는 로컬 검색만 완료되어 있으며 실제 GPT 호출은 연결되지 않았습니다.

학습지 생성과 학생별 오답 학습은 선택된 수업 자료에서 검색한 본문을 GPT 입력으로 전달합니다. 학생 대화의 참고 자료도 원문 페이지로 표시합니다. API 키 없이 다른 단원의 질문 생성을 GPT 결과처럼 표시하지 않습니다.


## 학습지 QR 자동 인식

학습지를 저장해 열면 학습지 ID·반 ID·내용 버전을 담은 QR이 생성됩니다. QR은 인쇄/PDF 저장에도 포함되며 학생 이름이나 정답은 담지 않습니다. 저장 완료와 QR 이미지 로딩 이후에만 출력할 수 있습니다.

답안 채점에서 JPG·PNG 또는 PDF를 선택하면 브라우저가 QR을 읽고 서버에서 등록된 학습지·반·버전을 검증한 뒤 학습지를 자동 선택합니다. 사진은 크기 조정 후, PDF는 20쪽 이하 전체를 검사합니다. 최대 파일 크기는 10MB입니다. 서로 다른 학습지 QR이 섞이면 분리 업로드를 요청합니다. 인식되지 않는 답안은 학습지를 직접 선택할 수 있습니다.

실제 QR 생성과 인식은 GPT·OCR API 키 없이 작동합니다. 손글씨 답안 추출은 OCR_BACKEND_URL 연결이 별도로 필요합니다. 외부 OCR 요청에는 확인된 qrPayload와 학습지 ID를 함께 전달하고 응답의 worksheetId를 검증합니다.


## 자료를 보면서 문제 생성

수업 자료 카드의 제목 또는 ‘PDF · 문제 생성’을 누르면 같은 화면에 자료 작업 공간이 열립니다. 왼쪽에서 학습지 제목·문항 유형·수를 정하고 오른쪽에서 원문 PDF의 페이지를 넘길 수 있습니다. 생성 후에는 PDF를 유지한 채 문항·정답·채점 기준을 검토합니다. 저장하면 기존 QR 포함 학습지 출력으로 이어집니다. 다른 자료로 이동해도 작업 중인 문항 초안은 해당 화면 세션에 보관합니다.

바로 열기: http://localhost:4173/teacher?view=materials&material=teacher-galaxy

API 미연결 시 우리은하·조선 건국·순환계는 원문을 바탕으로 준비한 시연 문항을 사용하며 이를 표시합니다. 각 자료에 유형별 3개씩 준비되어 있습니다. 혼합형은 화면에서 최대 6개, 단일 유형은 최대 3개를 선택합니다. 실제 AI 모드는 기존 /api/worksheets/generate에 선택 자료 ID와 유형·문항 수·학습 목표를 전달합니다. PDF 본문과 RAG 검색은 기존 등록 자료를 사용합니다.


## T/F 문제와 문장 수정

수업 자료에서 문항 유형을 T/F로 선택하거나 문항 편집기에서 T/F로 변경할 수 있습니다. 교사는 참·거짓 정답을 정하고 F일 때 틀린 부분과 바르게 고친 문장을 정답 기준으로 입력합니다. 시연용 문항은 밀도·우리은하·조선 건국·순환계에 각 3개씩 제공됩니다.

학생 화면의 ‘T/F 문제 풀기’에서 판단을 선택합니다. F를 선택하면 틀린 부분과 고친 문장이 필수입니다. 제출한 응답은 학생별로 SQLite에 저장되며 교사는 상세 화면에서 확인하고 채점을 확정할 수 있습니다. API 연결 시 교사 채점과 학생 웹 직접 제출 모두 GPT 의미 채점을 사용합니다. API 미연결 시 정확히 일치하는 수정 답안은 정답, 표현이 다른 수정 답안은 교사 검토로 표시하며 의미 일치를 자동 판정하지 않습니다.
